Privacy Policy

Personal Google Calendar integration · Last updated: 11 November 2026

In short: this is a private integration used by one person — its owner. It reads and writes calendar events for the owner's own Google account. It stores no analytics, shares nothing with third parties, and serves no other users.

Who operates this integration

A private Google OAuth client registered by Ben Hauptvogel, Berlin, Germany, and used solely for his own Google account. It is not a public product, it has no sign-up, and no other person can use it or is affected by it.

What data is accessed

The integration requests a single Google permission: view and edit events on the owner's own calendars (https://www.googleapis.com/auth/calendar.events).

  • Calendar events: titles, descriptions, times, locations, attendee addresses, and reminders.
  • No Gmail, Drive, Contacts, Photos, or health data is requested or accessible.
  • No data belonging to any other Google account is ever fetched.

How the data is used

Only to serve the owner's own requests — listing upcoming events, creating an appointment, moving or deleting an event. There is no profiling, advertising, or marketing use.

Where it is stored

Calendar content is fetched from Google on demand and is not warehoused in a database. Two things persist on a privately operated server that only the owner controls:

  • An OAuth refresh token, stored in a file readable only by the server process, used to obtain short-lived access tokens.
  • The OAuth client credentials issued by Google Cloud, likewise restricted to that server.

No analytics or advertising service receives any of this data.

Sharing

No sharing. Data is not sold, rented, published, or disclosed to third parties. The only outbound calls go to Google APIs (googleapis.com, oauth2.googleapis.com) to read or modify the owner's own calendar.

Retention and deletion

Data remains accessible only while the OAuth grant exists. Access can be revoked at any time at myaccount.google.com/permissions, which immediately invalidates the stored token. Deleting the token file removes the integration entirely.

Security

Credentials are stored with permissions limited to the server user, the OAuth callback is handled locally, and no client secret or token is published on this website.

Your rights

As the sole data subject, the owner can request information about, correction of, or deletion of any stored data at any time using the contact below. Under the GDPR this includes the rights of access (Art. 15), rectification (Art. 16), erasure (Art. 17), and data portability (Art. 20).
